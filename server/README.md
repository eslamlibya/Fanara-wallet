# خادم فنارة (200 مستخدم)

خادم بلا أي مكتبات خارجية (Node 22.5 أو أحدث)، وقاعدة بيانات SQLite، ودفتر حسابات مزدوج القيد.
التطبيق نفسه (`index.html`) يعمل مع الخادم تلقائيًا: إذا وجد `/api/health` يتحول إلى وضع الخادم (حسابات حقيقية، أرصدة على الخادم).

## تشغيل محلي
```
ADMIN_KEY=كلمة-سر-طويلة node --no-warnings server/server.js
```
ثم افتح `http://localhost:3000` و`http://localhost:3000/admin` للإدارة.

## متغيرات البيئة
| المتغير | المعنى | الافتراضي |
|---|---|---|
| `ADMIN_KEY` | مفتاح لوحة الإدارة (بدونه تتعطل الإدارة) | — |
| `DB_PATH` | مسار ملف قاعدة البيانات (ضعه على قرص دائم) | `server/data/fanara.db` |
| `MAX_USERS` | أقصى عدد مستخدمين | 200 |
| `DAILY_LIMIT_LYD` | حد الإرسال اليومي لكل مستخدم بالدينار | 5000 |
| `LIVE_MODE` | `true` يخفي سطر «نموذج أولي» من الإيصالات. لا تفعّله قبل وجود ترخيص وشريك دفع حقيقي | false |
| `PORT` | المنفذ | 3000 |

## كيف يدخل الناس ويحصلون على رصيد
1. **الدخول بدعوة:** من `/admin` أنشئ رموز دعوة وأعطها للمستخدمين. لا أحد يسجل بدونها.
2. **الشحن:** يسلّمك المستخدم نقدًا (أو تحويلًا مصرفيًا). تنشئ له رمز شحن بالقيمة من `/admin` فيدخله في التطبيق.
3. **الكروت:** أضف رموز كروت حقيقية اشتريتها من الموزّع إلى المخزون من `/admin`. عند الشراء يأخذ المستخدم رمزًا واحدًا ولا يتكرر.
4. **كلمة المرور المنسية:** من `/admin` أعد تعيينها يدويًا (لا توجد رسائل SMS).

## فحص التوازن
زر «فحص الحالة والتوازن» في `/admin` يتحقق من: مجموع القيود = 0، كل رصيد = مجموع قيوده، لا رصيد سالب.
وعلاقة الأمانة: `مجموع أرصدة المستخدمين = −(cash + fees + store)`. إن اختلّ شيء فتوقف وراجع السجل.

## النشر
- **Render:** خدمة Web من هذا المستودع (Docker). أضف **Disk** مثبّتًا على `/data` (لا يعمل القرص على الخطة المجانية)، وعرّف `ADMIN_KEY`.
- **VPS:** `docker build -t fanara . && docker run -d -p 80:3000 -v fanara-data:/data -e ADMIN_KEY=... fanara` وضع أمامه HTTPS (Caddy أو Cloudflare).
- **مهم:** يجب أن يكون الموقع على **HTTPS** دائمًا، وخذ نسخة احتياطية يومية من ملف قاعدة البيانات (`DB_PATH`).
